# 폴더별 공유 키 설계와 완료 기준

Date: 2026-09-06. Baseline: `22664cf559aa08063e0e7756e5babc12ed67b107`.

## 목적과 작업 기준

사용자는 폴더를 공유하고 읽기 전용 또는 읽기/쓰기 키를 복사한다. 다른
기기에서는 키를 붙여넣고 저장할 폴더를 선택하면 자동으로 연결하고 계속
동기화한다. 장치 ID, 주소, 포트, 양쪽 허용 목록, 수신 역할은 기본 과정에서
요구하지 않는다. 계획이나 API 모형으로 완료를 대신하지 않는다.

현재 `main`은 여섯 작업의 보안·버그·성능 개선을 통합한 커밋이다. 분리된
`share-key-sync-update` worktree가 같은 커밋에서 시작했고 처음에는 깨끗했다.
`preserve/main-wip-20260906`은 실제로 존재하며 커밋은
`329ab2e79dd91963e142711426ac074a001557af`이다. 그 브랜치에는 별도의 React
콘솔과 지속 관리 계층이 있다. 실행 중인 8390번 웹 콘솔은 이 개선본의 화면을
제공한다. 개선본의 필요한 UI·관리 기능을 선별 통합하되 기존 엔진 파일을
오래된 버전으로 덮어쓰지 않는다. 기존 worktree와 보존 브랜치는 삭제하지 않는다.

실행 중인 사용자 콘솔과 데이터는 읽기 전용으로 조사한다. 체험용 서버는 별도의
테스트 데이터와 identity를 사용한다. 기존 Linux CI 통과와 Windows 경로 출력
테스트 실패는 새 변경의 결과와 구분하여 기록한다.

## 선택한 구조

공유를 만든 기기가 해당 공유의 가입·권한 관리와 동기화 중계의 권한자다.
새 관리 연결에는 기기별 하나의 지속 identity와 iroh endpoint를 사용하고,
`deltaweave/share/3` ALPN에서 공유 ID별로 분리된 root/index/store를 선택한다.
한 기기에 여러 공유가 있어도 endpoint identity를 다른 기기에 복제하지 않는다.
기존 수동 연결의 identity와 인덱스는 그대로 보존한다.

통신 identity와 인덱스에 저장된 논리적 ReplicaId는 구분한다. 기존 폴더는
이미 DB에 결합된 ReplicaId를 공유 설정에 그대로 보존하여 새 endpoint로도
동일한 인덱스를 연다. 새 공유의 논리 ID는 로컬에 지속 생성한다. 정상 인덱스의
root/replica 결합 검사를 약화하거나 과거 version vector를 초기화하지 않는다.

가입자는 발급 기기의 인증된 endpoint에만 연결한다. 가입자는 공유의 스냅샷을
다른 가입자에게 제공하지 않는다. 읽기 전용 가입자의 기록을 읽기/쓰기 가입자가
가져가 재전파할 수 있는 mesh 경로는 없다. 가입자가 받아들이는 기록은 발급
기기의 iroh 인증 채널에서만 오며, 발급 기기는 모든 입력에 쓰기 권한을 검사한다.
이 신뢰 경계는 문서와 공격 테스트로 증명한다. 기존 unsigned version vector를
암호학적 서명이라고 설명하지 않는다.

검토한 대안은 모든 기록에 서명과 권한 인증서를 붙이는 mesh, 짧은 키를 위한
외부 조회 서비스다. 전자는 기존 인과관계·충돌 데이터 형식을 크게 바꾸고,
후자는 별도 서비스와 운영 비용이 생긴다. 발급 기기 중심 구조는 기존 무결성·
인과관계 처리를 재사용하면서 요구된 권한 경계를 만든다. 비용은 발급 기기가
꺼져 있을 때 가입과 동기화가 대기한다는 점이다. 오프라인 mesh를 제공한다고
주장하지 않는다.

기본 네트워크는 기존 iroh N0의 검색·릴레이 기능이다. 키에 최초 접속 힌트와
발급자의 공개 identity를 넣고, 주소가 바뀌어도 공개 identity 조회로 연결한다.
직접 연결 전용 모드는 고급 설정과 재현 가능한 테스트에서 제공한다. 직접 연결
티켓의 주소가 오래되었거나 인터넷 검색·릴레이를 사용할 수 없으면 구체적으로
오프라인/접속 실패를 표시하고 재시도한다. 외부 네트워크 실험과 로컬 실험의
증거를 구분한다.

## 키와 지속 권한

키에는 버전, 공유 ID, 발급자 공개 identity, 폴더 이름, 권한, 발급 ID, 충분한
OS 난수 bearer, 만료 정보, 접속 힌트를 담는다. 버전이 지정된 정규 직렬화 본문에
iroh가 제공하는 Ed25519 서명을 사용하고, 제한된 크기·엄격한 파서로 손상과
변조를 거부한다. 키 길이를 임의로 짧게 제한하지 않는다. 폴더 이름과 권한은
서명 확인 후 미리 볼 수 있으나 폐기 여부는 온라인 발급 기록으로 검증한다.

발급 기록은 `{id, share_id, secret_hash, permission, expires_at, revoked_at}`,
기기 가입 기록은 `{share_id, endpoint_id, permission, enrolled_at, revoked_at}`로
구분한다. bearer의 실제 발급 기록을 대조하고 클라이언트가 보낸 권한 문자열을
권한으로 사용하지 않는다. 관리자 로그인 키, 장치 비밀 키, 공유 키는 별개다.
공유 키에는 관리자 자격 증명이나 장치 개인 키가 들어가지 않는다.

검증과 가입은 구분한다. 사용자의 저장 폴더 선택과 동기화 시작이 가입을
완료한다. 발급자가 오프라인이면 서명을 확인한 키와 선택한 폴더를 사설 상태에
보관하고 대기할 수 있다. 실제 가입 성공 전에는 동기화나 온라인으로 표시하지
않는다. 가입 후에는 기기 identity와 지속 권한 기록으로 재연결한다.

발급자가 키를 폐기하면 신규 가입만 중단된다. 연결 기기를 해제하면 기존
연결·요청·세션에도 권한 해제가 적용되며 재시작 후에도 유지된다. 모든 요청,
스냅샷 세션의 후속 요청, 디스크 반영 직전에 현재 권한을 확인한다. 진행 중인
연결은 닫고, 해제 응답은 필요한 작업이 안전하게 종료된 뒤 반환한다.

구체적으로 namespace 변경은 최종 권한 검사부터 파일 반영과 인덱스 채택까지
하나의 공유별 gate 안에서 실행한다. 해제는 지속 상태에 기록하여 새 요청을
막은 뒤 기존 연결을 닫고 그 gate와 이미 시작된 blocking 작업·chunk writer의
종료를 기다린다. async 작업 취소를 디스크 작업 취소로 간주하지 않는다.
해제 완료 응답 뒤에는 새로운 파일·인덱스 반영이나 데이터 송신이 없어야 한다.

공유 기기만 키와 구성원을 관리한다. 읽기/쓰기 권한은 관리 권한이 아니다.
해제한 identity의 재가입은 거부한다. 아직 유효한 키로 새로운 identity를 만들어
가입할 수 있다는 한계와 두 권한 키를 교체해야 하는 상황을 UI에 설명한다.
폐기로 이미 전달된 파일을 회수할 수 있다고 표현하지 않는다.

## 동기화 규칙

읽기/쓰기는 기존 Merkle 비교, version vector 인과관계, 충돌 사본, CDC/CAS,
내용 해시 검증, 원자적 파일 반영과 재시작 복구를 재사용한다. 파일 추가·수정·
삭제와 디렉터리·메타데이터 변경은 모두 서버에서 공유 범위와 권한을 확인한다.

쓰기 요청의 출처 기록은 실제 인증된 기기, 권한 세대, 작업·record hash로 남긴다.
논리적 vector ID는 작성자 인증 표시로 쓰지 않는다. v3에서는 구성원의 논리 ID를
공유 안에서 고유하게 결합하고, 기존 인덱스에서 알려진 ID와 신뢰한 counter의
상한을 보존한다. 인증된 구성원 자신의 counter만 그 상한을 넘길 수 있고 다른
구성원의 counter를 위조하여 다음 편집을 overflow시키는 요청은 거부한다.
충돌 resolver의 정상 1회 증가, vector 크기와 overflow도 검사한다. 전역 로컬
counter는 다른 파일의 편집 때문에 건너뛸 수 있으므로 작은 증가량 제한은 두지 않는다.
기존 인과관계·동일 버전 내용 검사와 실제 충돌 알고리즘은 유지한다. 완전한
악성 RW의 모든 인과관계 주장에 대한 암호학적 증명이나 mesh는 제공 범위가 아니다.

새 참여자의 논리 ID는 발급자가 공유 안에서 생성·지속 예약한다. 일반 가입자가
과거 vector에 있는 ID를 임의로 선택하도록 허용하지 않는다. 기존 수동 연결
참여자의 인덱스를 이전할 때는 그 기기에 남아 있는 예전 identity로 이전 증명을
서명한다. 서명은 버전·도메인, 초대, 발급자·공유, 새 인증 endpoint, 예전 endpoint와
논리 ID에 결합하며, 서버는 예전 endpoint의 해시가 기존 논리 ID와 일치하는지
검사한 뒤 하나의 새 endpoint에 지속 결합한다. 예전 비밀 키는 로컬 증명에만
사용하고 전송하거나 새 transport identity로 복제하지 않는다. 발급자 자신의
폴더 전환은 신뢰한 로컬 관리 작업으로 기존 DB 결합을 읽어 예약한다. 예전 키가
없거나 별도 생성된 ID라서 증명할 수 없다면 원래 identity 복원을 안내하고
인덱스를 그대로 둔다. 자동 초기화나 검증 없는 역사 ID 재할당은 하지 않는다.
과거에 수신만 한 참여자는 발급자 vector에 자신의 ID가 없을 수 있다. 이 경우에도
유효한 예전 키 증명으로 그 키에서 유도된 ID를 예약할 수 있다. 발급자·resolver ID와
이미 활성 또는 폐기된 다른 구성원에 결합된 ID는 계속 거부한다.

읽기 전용에는 별도의 발급자 권위 스냅샷 적용 경로를 만든다. 단순히 기존
양방향 병합에서 업로드 버튼만 숨기거나 push만 생략하지 않는다. 로컬 추가·
수정·삭제는 원격으로 전파하지 않는다. 로컬 수정 또는 원격 삭제·종류 변경과
충돌하는 내용을 바꾸기 전에 비공개 복구 공간과 사설 상태의 기록에 내구성 있게
보관한다. 이 복구 공간은 공유 root 밖에 두어 재유입되지 않는다. 로컬 삭제는 원격의
파일을 다시 받는다. 비밀 상태 사본 경로·충돌 상태를 사용자에게 보여준다.
읽기 전용은 동기화 권한이며 운영체제의 readonly 속성과 별개다.

읽기 전용 인덱스에서 로컬에서 생긴 버전과 tombstone이 공유 기록으로 승격되지
않도록 권위 스냅샷을 교체한다. 스캔·사본 보존·파일 반영 사이의 로컬 변경은
재확인하여 새 작업을 잃지 않게 한다. 중단된 적용은 재시도해 복구한다.

복구 기록은 사본 경로와 예상 로컬 상태를 먼저 지속한 준비 단계, 사본 보존,
원격 상태 반영, 인덱스 채택, 완료 단계로 복구한다. 각 단계 중단 뒤에도 사본의
원본 경로를 알 수 있어야 한다. 마지막으로 신뢰한 발급자 스냅샷을 지속하고
인과관계가 이전으로 돌아가거나 동일 버전의 다른 내용, tombstone 없는 과거 경로
소실은 거부한다. 발급자 백업 복원의 이력을 다시 신뢰하는 작업은 명시적 재설정이다.

기존 파일의 보존은 대상 파일과 같은 파일시스템의 비공개 복구 공간으로 원자적으로
이동한다. 상태 저장소가 다른 파일시스템에 있으면 기본 복구 공간은 canonical root
부모 아래의 root별 비공개 디렉터리로 정하고 실제 장치·볼륨이 같은지 검사한다.
다른 등록 공유의 namespace와 겹치는 복구 위치는 사용하지 않는다. 안전한 같은
파일시스템 위치를 확보할 수 없으면 원본을 바꾸기 전에 실패하고 복구 위치 안내를
제공한다. 복사 후 원본을 지우는 대체 경로는 이미 열린 파일에 뒤늦게 기록되는
수정까지 보존할 수 없으므로 사용하지 않는다. 보존된 원본은 명시적 정리 전까지
남기며, 수신 임시 파일을 복구본으로 표시하지 않는다.

교체·삭제·종류 변경은 공통 보존 함수와 고유 시도 ID를 가진 기록을 사용한다.
보존 위치를 먼저 지속한 뒤 이동하고, 잡힌 원본을 다시 검사하며, 새 로컬 파일이
생겼다면 덮어쓰지 않는 원자적 설치·복원으로 처리한다. 인덱스 채택 이후에만 해당
단계를 완료로 표시한다. 재시작은 기록과 실제 경로를 함께 검사하고, 확인할 수 없는
복구본이나 경로는 삭제하지 않은 채 해당 폴더의 동기화를 멈춘다.

새 공유 endpoint는 v1/v2를 등록하지 않는다. 관리 root에 대한 지속 소유 표시와
잠금으로 현재 CLI와 기존 관리 경로의 v1/v2 재개방도 거부한다. 표시는 root 밖에
두어 원격 동기화로 지우거나 덮을 수 없게 한다. 로컬 OS 관리자나 오래된 바이너리로
보호를 제거하는 경우는 원격 권한 통제의 범위 밖임을 명시한다.

모든 현재 버전 CLI와 관리 경로는 `--state`나 웹 data dir와 독립된 고정된
호스트·사용자별 사설 root 소유권 registry를 사용한다. 공통 파일 잠금 아래에서
canonical 경로 구성요소로 동일·상위·하위 겹침을 검사한 뒤 등록하고, 등록별
잠금은 해당 작업 수명 동안 유지한다. 단순 문자열 접두사 비교는 사용하지 않는다.
따라서 관리 폴더의 상위 폴더를 수동 공유해 내부 파일을 공개하거나 쓰는 것도 거부한다.
state 경로를 바꾸거나 심볼릭 링크 별칭을 사용해도 같은 검사에 도달한다.

같은 registry는 기기 identity·catalog, 웹 관리 상태, 공유별 사설 상태와 복구
공간도 비공개 경로로 지속 예약한다. public root와 비공개 경로는 어느 쪽을 먼저
등록해도 동일·상위·하위로 겹칠 수 없다. 사설 디렉터리끼리는 중첩할 수 있다.
registry 자체의 고정 경로도 항상 비공개로 취급한다. 아직 없는 대상 경로는 가장
가까운 기존 canonical 조상과 남은 구성요소로 먼저 검사하며, 거부할 요청은
디렉터리나 공유 catalog를 만들기 전에 종료한다. 검사·생성·재검증·등록은 공통
잠금의 같은 임계 구역에서 수행한다.

관리 등록은 지속하며 canonical root의 부모 디렉터리에 결정적 sidecar도 둔다.
registry나 표시가 손상·불일치하면 거부한다. 일시적인 legacy 등록은 수명 잠금이
풀린 경우에만 정리한다. 관리 폴더의 파일을 기존 `push`의 직접 source로 보내는
경로도 같은 검사로 거부한다. 로컬 스캔·manifest 생성은 파일을 원격 공개하는
행위가 아니므로 유지한다. 신뢰한 OS 사용자가 사본을 다른 경로에 만들어 명시적으로
내보내는 행위는 원격 권한 통제 밖이다. UI에서 연결을 제거해도 관리 표시는 남는다.
표시·registry·관리 설정의 부분 완료 상태는 재시작 때 조정한다.

## 콘솔·호환성

기존 개선 콘솔의 Manrope, Noto Sans KR, IBM Plex Mono, 숲색 계열 토큰,
공통 버튼·대화상자·탐색·활동·설정 화면을 유지한다. 관리 화면에 랜딩 페이지용
장식이나 과도한 애니메이션을 추가하지 않는다. UI 보존, 낮은 모션, 기존 정보
밀도를 기준으로 접근성 지침을 적용한다.

주 동작은 `폴더 공유`와 `키로 연결`이다. 서버가 관리하는 폴더를 탐색하는 실제
폴더 선택 UI를 제공하며 현재 브라우저의 임의 업로드 폴더와 혼동하지 않는다.
공유 결과에는 폴더, 저장 위치, 권한, 연결 기기, 현재 연결 상태를 표시한다.
연결 대기, 상대 오프라인, 최초 동기화, 최신 상태, 로컬 변경 충돌, 권한 해제,
잘못된 키를 구분한다. 등록 사실은 온라인이나 동기화 완료의 증거가 아니다.

긴 키 입력, 복사 성공·실패, 키보드 이동·포커스 복원, 오류 연결 라벨, 모바일
오버플로와 대비를 실제 브라우저로 검증한다. 비밀 키는 활동, 로그, 분석, 오류,
브라우저 캡처에 남기지 않는다. 기존 인증, Host, Origin, CSRF, 경로 보호 테스트를
유지하고 새 API에도 같은 보호를 적용한다.

기존 CLI와 단일 폴더 `deltaweave-web` API/실행 인자는 계속 동작한다. 개선 콘솔의
기존 폴더·연결·설정 파일은 자동으로 읽는다. 수동 연결은 고급 설정에 남긴다.
기존 폴더를 공유 키 방식으로 전환할 때 파일, 인덱스, identity와 상태를 보존한다.
상대 기기는 같은 폴더를 선택해 키로 전환하며 폴더 삭제와 재등록을 요구하지 않는다.
전환 시 수동 프로토콜의 종료와 상대에게 새 키가 필요한 영향을 명시한다.

## 완료 증거 행렬

| 요구 | 필요한 실제 증거 |
| --- | --- |
| 작업 기준·보존 | refs/worktree 상태, live UI 비교, 선별 diff, main 보호 회귀 |
| RW 연결 | 독립 identity, 키만으로 가입, 양방향 추가·수정·삭제 |
| RW 무결성·충돌·복구 | 기존 회귀 + 동시 수정 충돌 사본 + 실제 프로세스 재시작 |
| RO 수신·비전파 | 원격 추가·수정·삭제 수신, 로컬 변경·삭제 후 발급자/다른 가입자 확인 |
| RO 사본 보존 | 로컬 수정과 원격 갱신 충돌, root 밖 사본의 내용 및 재유입 불가 |
| 강제 권한·범위 | RO 직접 push/delete/metadata, v1/v2/CLI, 다른 share ID 모두 거부 |
| 변경 출처 | 변조 RO 스냅샷을 다른 RW 기기가 수용·전파하지 않는 실제 연결 시험 |
| 키 파서 | 손상·권한 변조·읽기 키 상승·미지원 버전·만료·폐기 거부와 복구 안내 |
| 기기 수명주기 | 키 폐기와 구성원 해제 차이, 현재 세션 중단, 재시작 후 상태, 재가입 정책 |
| 검색·회복 | 지원하는 네트워크의 자동 접속, 발급자 오프라인·단절 후 자동 재개 |
| UI 종단 | 실제 브라우저 복사 → 다른 기기에 붙여넣기 → 폴더 선택 → 실제 파일 내용 |
| 접근성·비밀 | 긴 키/복사 실패/키보드/포커스/라벨/모바일/대비, 캡처·로그 비밀 검사 |
| 호환·이전 | 기존 CLI/API/콘솔 설정·폴더·데이터 형식의 회귀, 삭제 없는 이전 |
| 전체 품질 | fmt, clippy, workspace tests/doc tests, rustdoc, UI tests/build, release build, self-test |
| 플랫폼 | 필요한 Windows CI 실행 결과, 실행 못 한 플랫폼·외부망은 미검증으로 기록 |
| 전달 | 문서·마이그레이션, 격리된 미리보기 주소, 한국어 연결 방법·권한·검증·제약 보고 |
| 반영 | 필수 검사 후 로컬 main 반영, 원격 push가 승인된 경우 push와 원격 CI 확인 |

이 표의 모든 항목은 현 상태의 직접 증거로 평가한다. 단위 테스트 또는 화면
모형만으로 넓은 동작을 통과로 판정하지 않는다. 검증 실패를 skip, 테스트 삭제,
권한 완화로 숨기지 않는다. 사용자는 구현 결정을 자율적으로 내리고 작업을 끝까지
수행하도록 승인했다. 원격 push는 아직 별도로 승인된 기록이 없으므로 검증된
구체적 변경이 준비된 다음 필요한 최종 단계에서 확인한다.
