# DeltaWeave Web UI Implementation Plan

> For agentic workers: use superpowers:subagent-driven-development to execute the independent tasks and review their integration.

**Goal:** Deliver a usable local browser interface for real DeltaWeave scanning, receiving and verified synchronization.

**Architecture:** New `deltaweave-web` binary serves embedded native web assets and a protected HTTP API. Existing library engines own all data operations. Frontend DOM updates consume actual API state.

**Tech Stack:** Rust 1.91, Tokio, axum 0.8, existing DeltaWeave libraries, native HTML/CSS/ES modules, Node test runner.

**Spec:** `docs/superpowers/specs/2026-09-05-web-ui-design.md`.

## Global constraints

- Preserve all pre-existing CLI changes; add the new crate to the workspace without replacing existing manifest changes.
- Loopback HTTP, session token, same-origin/Host validation, explicit confirmation, allow-listed receiving, no overlapping private/public paths.
- No mock production data or disconnected native fallback. Use actual ScanReport/SyncReport fields.
- Korean light-theme product UI; dials 2/1/5; retain the required HTML IDs and API contract from the spec.
- No deployment, remote publish, branch import, or modifications to the original sync business rules.
