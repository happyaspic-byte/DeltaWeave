# DeltaWeave 로컬 웹 UI

`deltaweave-web`은 선택한 폴더를 스캔하고, 허용한 기기와 직접 연결해 양방향 동기화를 한 번 실행하는 로컬 관리 화면입니다. HTML·CSS·JavaScript가 Rust 실행 파일에 포함되어 있어 별도의 프런트엔드 빌드나 Node.js 서버가 필요하지 않습니다. 소스에서 실행하려면 Rust 1.91 이상이 필요합니다.

## 실행

저장소 최상위에서 실행합니다. `--root` 폴더는 미리 만들어야 하며, `--state`는 동기화 폴더와 분리합니다.

```bash
mkdir -p ./shared-a
cargo run --locked -p deltaweave-web -- \
  --root ./shared-a \
  --state ./private/web-a
```

시작하면 표준 출력에 `url`, `root`, `endpoint_id`가 담긴 JSON 한 줄이 나옵니다. `url`의 `http://127.0.0.1:7840/#token=…` 주소 전체를 같은 컴퓨터의 브라우저에서 엽니다. 표시된 실제 주소를 사용하세요. `localhost`로 바꾸면 Host 검증에 거부될 수 있습니다.

이 링크의 토큰은 해당 프로세스를 제어할 수 있는 인증 정보입니다. 공개하거나 상대 기기에 전달하지 마세요. 화면은 토큰을 주소에서 지우고 탭의 `sessionStorage`에 보관합니다. 서버를 다시 실행하면 새 토큰이 생성되므로 새 링크로 접속해야 합니다. 상대에게 전달할 값은 공개된 **기기 ID (`endpoint_id`)**와 수신 주소입니다.

| 옵션 | 기본값·조건 |
| --- | --- |
| `--root` | 필수. 이미 존재하는 동기화 폴더 |
| `--state` | 현재 작업 폴더 기준 `.deltaweave-web` |
| `--identity` | 지정하지 않으면 `STATE/identity.key` |
| `--bind` | `127.0.0.1:7840`; 루프백 IP만 허용 |
| `--peer-bind` | `0.0.0.0:0`; 수신용 QUIC/UDP 주소, `0`은 자동 포트 |

## 두 기기 연결 순서

1. 양쪽에서 서로 다른 동기화 폴더와 비공개 상태 폴더로 실행하고 각자의 로컬 웹 화면을 엽니다. 한 컴퓨터에서 시험한다면 두 번째 프로세스에는 `--bind 127.0.0.1:7841`처럼 다른 HTTP 포트를 지정합니다.
2. A의 기기 ID를 B의 상대 기기 ID 입력란에 넣고 **이 피어의 수신 대기**을 누릅니다. B는 입력한 A만 허용합니다. 자신의 ID는 지정할 수 없습니다.
3. B 화면의 기기 ID와 직접 연결 주소를 A에 입력합니다. 주소는 `127.0.0.1:7941`, `192.168.1.20:7941` 같은 IP와 포트이며, IPv6는 `[::1]:7941` 형식입니다. 호스트 이름이나 포트 없는 주소는 받지 않습니다.
4. A에서 양방향 파일 변경에 동의한 뒤 동기화를 실행합니다. 양쪽 폴더가 변경될 수 있으며, 완료 결과에는 실제 검증된 동기화 보고서가 표시됩니다.
5. B에서 로컬 스캔이나 동기화를 실행하려면 먼저 **수신 대기 중지**를 누릅니다. 수신·스캔·동기화는 동시에 실행되지 않습니다.

같은 컴퓨터에서 두 번째 기기를 시험하는 실행 예입니다.

```bash
mkdir -p ./shared-b
cargo run --locked -p deltaweave-web -- \
  --root ./shared-b \
  --state ./private/web-b \
  --bind 127.0.0.1:7841 \
  --peer-bind 127.0.0.1:7941
```

LAN에서 B가 `192.168.1.20` 주소를 사용하는 경우에는 B를 다음처럼 실행할 수 있습니다. IP는 실제 B의 인터페이스 주소로 바꾸고, A가 해당 UDP 포트에 접근할 수 있어야 합니다.

```bash
cargo run --locked -p deltaweave-web -- \
  --root ./shared-b \
  --state ./private/web-b \
  --peer-bind 192.168.1.20:7941
```

`--peer-bind`는 파일 교환용 주소입니다. HTTP 관리 화면은 여전히 B 자신의 `127.0.0.1:7840`에만 열립니다. 상대 기기에서 이 HTTP 주소를 여는 방식으로 관리하지 않습니다. 이 웹 UI의 수신과 동기화는 직접 연결만 사용하며 릴레이나 인터넷 주소 검색은 사용하지 않습니다.

## 결과 확인과 복구

스캔은 실제 파일과 인덱스를 읽습니다. 목록은 최대 200개 기록을 표시하며 전체 기록 수를 함께 제공합니다. 최근 20개 작업은 성공·실패와 오류 내용을 기록합니다. 이 UI는 사용자가 요청한 스캔과 1회 동기화를 실행하며 자동 반복 동기화를 설정하는 화면은 없습니다.

새 작업이 실패해도 현재 프로세스의 이전 성공 보고서는 유지됩니다. 이전 결과를 현재 상태로 해석하지 마세요. 브라우저 연결이 끊기면 남은 결과가 오래된 정보로 표시되며 재연결할 수 있습니다. 파일명 충돌, 읽기 실패, 재시도 대기 때문에 스캔이 거부되면 작업 오류에 실제 경로와 이유가 표시됩니다. 긴 진단은 생략 개수와 함께 제한됩니다. 원인을 해결한 뒤 다시 스캔하세요.

수신 종료 후 저장소를 아직 해제하지 못했다면 중지 상태가 유지됩니다. 종료 오류가 표시된 경우 **수신 중지 다시 시도**로 다시 확인할 수 있습니다. 브라우저를 닫아도 이미 접수된 작업은 계속됩니다. 프로세스는 `Ctrl-C`로 종료하며, 접수한 작업이 끝나고 수신 연결과 저장소가 정리될 때까지 기다립니다.

## 경로와 접근 경계

- `root`와 `state`는 같거나 서로의 하위 폴더이면 안 됩니다. 심볼릭 링크도 실제 경로로 확인합니다. 서로 다른 폴더나 기기에는 각각 별도의 상태 폴더와 신원 파일을 사용하세요.
- 신원 파일은 동기화 폴더 밖에 둡니다. 동일한 신원 파일을 재사용하면 기기 ID가 유지됩니다. `identity.key`는 비밀 키이므로 공유하지 않습니다.
- 새 상태 폴더는 Unix에서 소유자 전용 `0700`으로 생성됩니다. 기존 폴더가 다른 사용자에게 열려 있으면 실행을 거부합니다. 이 앱의 전용 상태 폴더에 `chmod 700`을 적용한 뒤 실행하세요. 신원 파일은 Unix에서 소유자 전용 권한을 사용합니다.
- 모든 `/api/*` 요청은 프로세스별 Bearer 토큰을 요구합니다. 실제 HTTP 주소와 일치하지 않는 Host·Origin을 거부하며 CORS는 열지 않습니다. JSON 요청 본문은 8 KiB로 제한하고 CSP, 캐시 금지, 프레임 삽입 차단 등의 응답 헤더를 적용합니다.

웹 작업은 기존 DeltaWeave 인덱스·네트워크·동기화 라이브러리를 사용합니다. 충돌 사본, 변경 이력, 검증 및 비공개 복구 데이터는 기존 엔진 규칙을 따릅니다. 실행 중인 같은 상태 폴더를 다른 DeltaWeave 프로세스에서 함께 열지 마세요.
